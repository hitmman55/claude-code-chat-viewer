# Claude Code Chat Viewer

اقرأ سجل محادثاتك مع Claude Code في المتصفح. يحفظ Claude Code كل جلسة في ملف JSONL داخل `~/.claude/projects/`‎؛ افتح أحدها هنا فيتحوّل إلى شريط مقروء — رسائلك، وردود Claude، والتفكير (thinking)، واستدعاءات الأدوات ونتائجها، وتقارير الوكلاء الفرعيين — مع مرشّحات ووضع قراءة. ملف HTML واحد، بلا خادم ولا تثبيت، ويعمل دون اتصال؛ ولا يغادر جهازك أي شيء. يقرأ صيغة سجلات الجلسات حتى الإصدار 2.1.310 من Claude Code.

## لماذا

يكتب Claude Code كل جلسة في `~/.claude/projects/<project>/<session-uuid>.jsonl` — سطر واحد لكل سجل (رسالة المستخدم، رد النموذج، thinking، tool_use، tool_result، attachment، وما شابه). الملف الخام غير قابل للقراءة؛ الأوامر المدمجة مثل `/resume` و`/export` تعيد فتح المحادثة أو تُصدّرها كما هي، لكنها لا تتيح فحص سجل جلسة قديم مع استدعاءات أدواته وسجلاته الخدمية.

يحوّل هذا العارض ملف `.jsonl` إلى تدفق قابل للقراءة مع ألوان حسب الدور، وكتل خدمية قابلة للطي (thinking / tools / results)، ومرشّحات.

## ماذا يعرض

- **user** (أزرق) — رسائل المستخدم الحقيقية
- **assistant** (أخضر) — ردود Claude النصية
- **thinking** (بنفسجي) — التفكير الموسّع، مطويّ افتراضيًا
- **tool_use** (كهرماني) — استدعاءات الأدوات مع معاينة للمعاملات
- **tool_result** (سماوي / أحمر للأخطاء) — ردود الأدوات
- **meta / task-note** (أصفر) — حقن النظام و `<task-notification>` من الوكلاء الفرعيين
- **سؤال وإجابة** — استدعاء `AskUserQuestion` وإجابة الشخص في بطاقة واحدة
- **تقرير الوكيل الفرعي** (`↩ report`) — التقرير النهائي للوكيل الفرعي مع اسم مهمته؛ وعند انتهاء وكيل فرعي يعمل في الخلفية تظهر الرموز (tokens) · المدة · عدد استدعاءات الأدوات
- **الخطافات (hooks)** — تشغيل الخطافات وأخطاؤها (مرشّح خاص، معطّل افتراضيًا)
- **الضغط (compaction)** — فاصل يُظهر عدد الرموز قبل الضغط وبعده؛ ملخّص الضغط مطويّ
- **الصور** — لقطات الشاشة وصفحات PDF المحفوظة في السجل، تُعرض عند فتح كتلتها
- **system / attachment / ui-state** — سجلات خدمية (مخفية افتراضيًا)؛ القيم التي تعيد CLI كتابتها في كل دور (عنوان الجلسة، وضع الأذونات) لا تظهر إلا عند تغيّرها

كل كتلة تظهر كصف منفصل مع شريط ملون على اليسار. لا توجد فقاعات محادثة: هذا سجلّ، وليس دردشة.

## كيفية الفتح

اختر ما يناسبك:

**أ. تنزيل ملف واحد** — الأسهل. خذ HTML المستقل من [آخر إصدار](https://github.com/hitmman55/claude-code-chat-viewer/releases/latest)، واضغط عليه ضغطة مزدوجة. ملف واحد، يعمل دون اتصال للأبد.

**ب. نسخ المستودع** — إذا أردت التعديل على الكود. تحتاج إلى `index.html` ومجلد `lib/`.

**ج. استخدام العارض عبر الإنترنت** — افتح <https://hitmman55.github.io/claude-code-chat-viewer/>. لا شيء للتنزيل.

بعد الفتح، اضغط منتقي الملفات (أو اسحب ملفًا، أو استخدم زر «جرّب مثالاً») واختر سجلّ `.jsonl`.

تُحفظ سجلات Claude Code في:

```
~/.claude/projects/<project-slug>/<session-uuid>.jsonl
```

حيث `<project-slug>` هو مجلد العمل لديك بعد استبدال كل محرف ليس حرفًا أو رقمًا بـ `-`. مثال: `/home/user/my_proj` ← `-home-user-my-proj`.

## الميزات

### طرق تحميل الملف

- **منتقي الملفات** — اضغط «اختيار ملف» واختر `.jsonl`.
- **السحب والإفلات** — أسقط الملف في أي مكان على الصفحة. حدّ متقطّع يُشير إلى المنطقة. المجلدات والسحوبات غير المتعلّقة بالملفات تُرفض بلطف.
- **جرّب مثالاً** — في الحالة الأولى (عند الاستخدام عبر الإنترنت) يظهر زرّ يُحمّل `demo.jsonl` مضمّنًا يعرض أبرز أنواع الكتل.

### راحة القراءة

- **وضع القراءة** — مفتاح في الرأس لا يُبقي إلا ما قاله الناس وClaude: رسائلك (بما فيها `/compact` مع وسائطه)، وردود Claude النصية، وبطاقات السؤال والإجابة، وتقارير الوكلاء الفرعيين، وفواصل الضغط. بدون thinking، بدون استدعاءات أدوات، بدون سجلات خدمية. مناسب للتصفّح السريع أو لمشاركة عرض نظيف.
- **نسخ لكل رسالة** — زرّ `📋` في رأس كل مُدخل. ينسخ النصّ إلى الحافظة مع تأكيد `✓` لمدة 1.2 ثانية. يستخدم `navigator.clipboard.writeText` مع احتياطي `document.execCommand` لسياقات `file://`.
- **سطر إحصاءات صادق** — تُعدّ رسائل الشخص وردود النموذج بالقواعد نفسها التي يُبنى بها الشريط (مخرجات الأدوات وأغلفة الأوامر والإشعارات ليست رسائلك)؛ تُدمج التكرارات بعد `--resume`؛ ويُتخطّى سجل طلبات API (CLI 2.1.300+‎). تشير `? أنواع سجلات جديدة: N` إلى أنواع لا تعرفها هذه النسخة بعد: تظهر القائمة عند تمرير المؤشر، وتبقى هذه السجلات معروضة بصيغة JSON.
- **أسماء أدوات ودية** — الأدوات المعروفة تحصل على أيقونات (مثل `📖 Read file`، `🖥️ Shell`، `📝 Edit file`). الأدوات غير المعروفة / MCP → `🔧 {raw_name}`.
- **سمة تلقائية** — يتبع العارض `prefers-color-scheme` للنظام افتراضيًا. اضغط زرّ الشمس/القمر لتثبيت الاختيار؛ الاختيار المثبّت يستمرّ عبر الجلسات.
- **ست لغات للواجهة** — English، Русский، Español، Français، 中文، العربية. تنتقل العربية تلقائيًا إلى RTL. يوجد منتقي في الرأس، ويُحفظ التفضيل.

### الأداء والأمان

- **تحليل متدفّق** — يُقرأ `.jsonl` عبر `file.stream()` + `TextDecoderStream`، ولا يُحمَّل الملف كسلسلة واحدة.
- **افتراضية أصلية** — `content-visibility: auto` على كل سجل: يتخطى المتصفح تخطيط ورسم السجلات خارج الشاشة. يتحمّل آلاف السجلات.
- **عرض بأجزاء** — 500 سجل في كل جزء، وزر «عرض المزيد» لبقية السجلات.
- **مرشّحات** — ستة مربعات اختيار (thinking / tools / results / system / hooks / ui-state)، تُبدّل الفئات عبر صنف CSS واحد على الحاوية (دون إعادة عرض الصفحة).
- **عرض آمن من XSS** — تُهرَّب كل كتلة نصية _قبل_ تمريرها إلى محلّل markdown. لا يصل أي HTML خام من سجل الجلسة إلى DOM أبدًا، لذا لا حاجة إلى منقٍّ لـ DOM (sanitizer) أثناء التشغيل. يتم تحييد صور Markdown (تظهر كنص خامل، لا تُجلب أبدًا). الروابط مقتصرة على `http(s)` مع `rel="noopener noreferrer nofollow"`.
- **حدود للحجم** — تُقَصّ كتل النص عند 20000 محرف، والكتل الخدمية عند 5000. ينسخ زرّ `📋` ما هو معروض ضمن هذه الحدود، فلا تُرسل نقرة واحدة ميغابايتات من النص أبدًا؛ أما النص الكامل فلا يُتاح إلا عند الطلب، عبر `⤢`.
- **⤢ فتح كاملًا** — المُدخل المقصوص للعرض له زرّ `⤢`: يُفتح النص كاملًا في لوحة فوق الشريط (نص / markdown / JSON الأصلي للسجل)، مع «نسخ الكل» و«حفظ الملف». ولا يتغيّر ارتفاع الشريط.
- **احتياطي لـ `.json`** — إذا لم يكن الملف JSONL بل مصفوفة/كائن JSON عادية، يُحلَّل كقائمة سجلات.

## متطلبات المتصفح

- Chrome / Edge 85+‎
- Firefox 105+‎
- Safari 15.4+‎

`content-visibility: auto` (Firefox 125+‎ وSafari 18+‎) يقتصر دوره على تسريع تمرير الملفات الكبيرة؛ ومن دونه يعمل كل شيء، لكن بشكل أبطأ.

## الاعتماديات

واحدة فقط، مُحزَّمة محليًا في `lib/`:

- [marked](https://github.com/markedjs/marked) — markdown → HTML (~35 كيلوبايت)

بدون CDN، بدون شبكة، بدون Subresource Integrity. انسخ وشغِّل.

## ما المعلومات الشخصية في سجل الجلسة؟

يحتوي سجل الجلسة على أكثر بكثير من المحادثة. قبل مشاركة ملف `.jsonl` — أو لقطة شاشة للعارض — اعرف ما يحتويه:

- كل الرسائل وكتل التفكير (thinking) ومخرجات الأدوات، بما فيها محتوى الملفات ومخرجات الأوامر، وقد تتضمن مفاتيح أو رموز وصول (tokens) أو كلمات مرور؛
- المسارات المطلقة واسم المستخدم ومجلد العمل وفرع git، مكرّرة في كل سجل؛
- بريد حسابك الإلكتروني ونص موجّه النظام (system prompt) كاملًا ونص ملفات `CLAUDE.md` لديك — هذه السجلات مخفية افتراضيًا (مرشّحا system / ui-state)، ولا يُظهر ملخّصها ذو السطر الواحد إلا أعدادًا، وعند فتح أحدها يظهر محتواه؛
- الصور: لقطات الشاشة وصفحات ملفات PDF التي قُرئت خلال الجلسة؛
- سجلات طلبات API الكاملة (أسطر `api-request*`‎، CLI 2.1.300+‎؛ وقد تصل إلى نصف الملف) — يتخطّاها العارض، لكنها موجودة في الملف.

المخرجات الكبيرة جدًا ليست في سجل الجلسة: يحفظها Claude Code في `<session>/tool-results/` بجانب الملف، ولا يُظهر العارض إلا معاينة بحجم نحو 2 كيلوبايت مع المسار.

## الخصوصية

كل شيء يعمل محليًا في متصفحك. العارض نفسه **لا يُرسل أي طلبات شبكية تلقائية** — لا CDN، ولا تحليلات، ولا خطوط بعيدة. يتم تحييد صور Markdown المضمّنة في السجلات: تُعرض كنص خامل مع ظهور الرابط، لكن لا يتم جلبها. الروابط الخارجية (فقط `http(s)`) تُفتح في علامة تبويب جديدة فقط عند النقر عليها، مع `rel="noopener noreferrer nofollow"`. تبقى سجلاتك على جهازك. الصور المحفوظة داخل السجل (base64) تُرسم من الملف نفسه، ومن دون أي طلب شبكة كذلك.

## قيود معروفة

- الملفات التي تتجاوز حوالي 100 ميجابايت تحتاج إلى تحميل مفهرس حسب إزاحات الأسطر مع عرض نوافذ (غير مُنفَّذ).
- لا يمكن تصدير جلسة كاملة (الهدف هو العرض لا التحويل)؛ ويمكن حفظ مُدخل واحد عبر `⤢` ← «حفظ الملف».
- لا يوجد تلوين للصياغة في كتل الشيفرة (قرار مقصود للحفاظ على الحد الأدنى من الاعتماديات).
- تظهر الرسالة التي عدّلتها وأعدت إرسالها مرتين — فروع المحادثة لا تُرسم كشجرة بعد.
- تعرض شارات السجلات الخدمية اسم النوع الخام (مثل `hook_success`) دون ترجمة — وبذلك لا تحتاج الأنواع الجديدة إلى ترجمة.

## التطوير

كل الشيفرة في ملف HTML واحد. حرِّره مباشرة — الأنماط في `<style>`‎، والمنطق في `<script>`‎، والترجمات في كائن `I18N` في بداية السكربت.

فحص الصياغة وتشغيل الاختبارات من دون متصفح (دون تثبيت أي شيء):

```bash
node scripts/check-syntax.mjs  # syntax of the inline script
node --test test/*.test.mjs    # unit tests
```

الأجزاء التي لا تعتمد على DOM — فرز السجلات وجداول القواعد التي تقرر كيف يُعرض كل نوع سجل — تقع في قسمَي `triage` و`rules` من السكربت، وكلٌّ منهما بين `// ===== <name> =====` و`// ===== end <name> =====`‎؛ تقتطعها الاختبارات من `index.html` وتشغّلها في Node. يكفي عادةً لدعم نوع سجل جديد إضافةُ مُدخل واحد إلى جدول القواعد.
